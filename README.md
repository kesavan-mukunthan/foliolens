# FolioLens

Return and risk analytics for Indian mutual funds, written in Python. Every convention and tolerance the engine relies on is stated in [`CLAUDE.md`](CLAUDE.md) and enforced by a test.

## What works today

### Funds covered

- The committed test fixture (`fixtures/funds.csv`, `fixtures/nav_snapshots/nav.parquet`) holds daily NAV history for 13 share classes of 10 funds: large cap, mid cap, small cap, flexi cap, short duration debt, liquid, multi-asset, fund of funds and gold fund of funds.
- The fund page pipeline covers the flexi-cap category, direct plan, growth option.

### Returns (figures of record)

- NAV is held as `Decimal` from parquet `decimal128` through to the return result, with no float cast (`tests/invariants/test_decimal.py`).
- Growth-option NAV is the return basis. Month-end NAV is the NAV on the last trading day of the month, from a trading calendar derived across the fund cohort (`returns/calendar.py`, `returns/monthly.py`).
- Trailing 1Y, 3Y, 5Y and since-inception returns follow the SEBI rule: absolute below one year, CAGR from one year (`returns/engine.py`, `tests/invariants/test_annualization.py`).
- Time-weighted return equals point-to-point return on a cashflow-free series (`tests/invariants/test_twr.py`).

### Reconciliation of returns

The design is three-way: own implementation vs a library oracle vs the AMC-published figure. Two legs are built today.

- Own vs AMC-published: every trailing return in `fixtures/published_returns.csv` (AMC factsheets, as of 31 May 2026) is recomputed through the production pipeline and must land within 10 bps (`validation/reconcile.py`, `tests/validation/test_reconciliation.py`). On the committed fixture, 50 of 52 rows match and 0 mismatch. The other 2 are exempt with reasons recorded in `fixtures/reconciliation_exemptions.csv`; one is a known data-quality defect in fund 103340's pre-2009 NAV history.
- Own vs library oracle for returns is not yet built (`validation/oracle.py` is a placeholder).

### Risk and performance metrics

Computed as free functions over a monthly `float64` return series, with daily NAV used for drawdown and tail risk (`src/foliolens/analytics/`):

- Absolute: volatility, downside deviation, Sharpe, Sortino, Calmar, maximum drawdown, historical VaR and CVaR at 95%.
- Benchmark-relative (against TRI benchmarks): excess return, tracking error, information ratio, beta, correlation, R-squared, Jensen's alpha with its t-stat, Treynor, up and down capture, hit rate.
- Rolling 1Y, 3Y and 5Y returns, rolling excess return, rolling Sharpe, beta and correlation.
- Distribution: skew, kurtosis, share of positive months, best and worst month.
- Peer: percentile ranks within the category, category median and quartiles.
- Risk-free rate: the IIM-A 91-day T-bill series.

Own-vs-oracle tests run on frozen synthetic fixture series at a relative tolerance of `1e-6` (`tests/test_*_oracle.py`). Against empyrical-reloaded: volatility, downside deviation, Sharpe, Sortino, Calmar, maximum drawdown, VaR, CVaR, beta, Jensen's alpha, information ratio, up and down capture. Against pandas, NumPy or SciPy: the alpha t-stat, R-squared, rolling returns, skew, kurtosis and the category median and quartiles. The remaining metrics have closed-form unit and edge-case tests.

### Flexi-cap fund pages and PDF

- `python -m foliolens.report.flexipage` builds a `metrics.json` artifact for every flexi-cap direct-growth fund from stored NAV, benchmark TRI and the risk-free series, and aborts if more than 10% of funds fail to load.
- `python -m foliolens.report.flexipage.render` renders it into a static HTML site: a category page plus one page per fund with charts (growth of 10,000, drawdown, rolling excess return, rolling Sharpe rank). WeasyPrint prints each page to PDF through a print stylesheet.
- Per-fund commentary is generated by an LLM call, with a deterministic template fallback when the call fails.
- The pages cannot be rebuilt from this repository alone. They need benchmark TRI levels, a scheme master and the IIM-A series, which are not committed (see Data and licensing). The pipeline is tested end to end on a synthetic three-fund universe.

### Tests

`uv run pytest` on this commit: 676 passed, 1 expected failure. The expected failure is the NAV-jump guard on fund 103340, marked `xfail(strict=True)` so that it fails loudly once the data is fixed. The per-file list is in [`tests/TESTS.md`](tests/TESTS.md).

## Design

Anything investable is an `Investment` with a return series. Fund share classes and benchmarks are implemented; `Portfolio` and `Stock` are stubs. More in [`ARCHITECTURE.md`](ARCHITECTURE.md); build order in [`SCOPE.md`](SCOPE.md).

## Built on

Python 3.12 with [uv](https://docs.astral.sh/uv/). NAV data comes from AMFI via [mftool]; returns for cross-checking come from AMC factsheets.

## Running it

```bash
uv sync
uv run pytest
uv run mypy src
```

## Data and licensing

The MIT licence covers the code only, not any data in this repository or fetched by it.

- `fixtures/nav_snapshots/nav.parquet` is a frozen test snapshot of AMFI NAVs (fetched via [mftool]), kept solely so tests are reproducible. It is not a redistributed dataset; get current NAVs from AMFI.
- `fixtures/published_returns.csv` quotes trailing returns from AMC factsheets, each row carrying its source and as-of date, used only as reconciliation targets.
- Sources used in computation but never committed or republished: the IIM-A factor and risk-free library (citation-only; derived from CMIE Prowess and not licensed for redistribution) and benchmark TRI levels (subject to index-provider licensing).
